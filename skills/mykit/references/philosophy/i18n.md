# Internationalization

i18n은 화면 문구 치환만이 아니라 UI 계약의 일부다. 사용자에게 보이는 텍스트, 접근성 라벨,
검색 placeholder, 상태 메시지, validation 메시지를 같은 정책으로 다룬다.

## 기본 원칙

- 사용자 노출 문자열을 컴포넌트 소스에 직접 흩뿌리지 않는다.
- 번역 키는 화면 위치보다 기능 도메인과 사용자 의도 기준으로 설계한다.
- fallback locale 정책을 명시한다.
- 접근성 라벨도 번역 대상이다.
- 번역이 길어져도 UI가 깨지지 않게 레이아웃을 잡는다.

## 키 설계

- `common.close`, `settings.fontSlider`, `project.searchPlaceholder`처럼 안정적인 도메인 이름을 사용한다.
- 같은 문자열이라도 문맥이 다르면 키를 분리한다.
- interpolation 값은 label, count, value처럼 의미 있는 이름으로 둔다.
- 임시 화면 문구를 키로 만들 때도 나중에 유지 가능한 이름을 붙인다.

## 접근성과 i18n

- 아이콘 버튼, chip, slider, modal close 같은 비시각 텍스트는 `a11y.*` 또는 프로젝트의 접근성 namespace로 둔다.
- label은 보이는 텍스트 반복에 그치지 않고 조작 결과를 설명한다.
- viewport나 상태에 따라 조작 결과가 바뀌면 접근성 문구도 분기한다.

## 액션 프롬프트에서 확인할 것

- 새 컴포넌트가 화면 텍스트를 추가하는가.
- placeholder, empty, loading, error, success 문구가 필요한가.
- 접근성 label이나 value text가 필요한가.
- locale별 데이터 파일, message catalog, namespace가 어디인지.
- 키 누락을 잡는 테스트가 이미 있는지.

## 검증

- 지원 locale 간 key set이 일치하는지 확인한다.
- 새 키를 추가했다면 모든 지원 locale에 값을 넣는다.
- 동적 interpolation 값이 빠지지 않는지 확인한다.
- 긴 번역 문자열과 한국어/영어 단어 길이 차이를 고려해 레이아웃을 확인한다.
